## 1. 동작 명세

이 모듈이 무엇을 하는가. 코드에서 자명하지 않은 동작 규칙·상태 전이·외부 의존을
사람이 읽을 수 있게. 자유 형식. 표·다이어그램·코드 블록 허용.

**적지 말 것:** 함수 시그니처, 파일 구조, 변수명 — `git ls-files` / `grep`으로 복원 가능.
**적을 것:** "왜 이렇게 동작해야 하는가", "이렇게 동작해야만 한다"는 제약.

## 2. Invariants — 깨지면 BLOCKED

implementer가 작업 중 다음 중 하나라도 위반·위험을 감지하면 즉시 멈추고 사용자에게 보고.

### 의존성 맵

특정 파일을 수정할 때 같이 확인해야 하는 파일/기능. 회귀가 자주 났던 짝만 적는다.

| 수정 대상 | 같이 확인할 곳 |
|-----------|---------------|
| `path/to/A` | `path/to/B`, `path/to/C` |
| `path/to/B` | ... |

### 불변 조건

지키지 않으면 시스템이 망가지는 규칙. 한 줄씩.

- {예: "ID는 단방향 매핑 — slug→id 만 있고 역방향은 없음"}
- {예: "결제 금액은 서버에서 재계산 — 클라이언트 값 신뢰 금지"}

### 충돌 감지 (STOP & ESCALATE)

다음 중 하나라도 해당하면 즉시 멈추고 사용자에게 보고:

- 동일 state/변수를 다른 용도로 사용
- 기존 플로우의 조건/분기 변경
- 기존 데이터 모델 필드 변경·삭제
- 의존성 맵에서 2개 이상 영향
